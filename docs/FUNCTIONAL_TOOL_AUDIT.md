# Functional-tool implementation audit

## Conclusion and scope

The cycle atlas remains an analysis of community-level predicted-protein annotation records. It is not a reconstruction of organism-level metabolism, measured enzyme abundance or biochemical flux. This audit examined relevant implementations in all 11 previously proposed programs, plus specialist annotation resources, RbiMs, clubSandwich and DRAM's pinned rules dependency: 25 repositories in total.

This is a targeted scientific implementation audit, not an exhaustive review of every line, dependency or historical release. The [source manifest](../config/gene_biogeography/upstream_sources.json) identifies 114 retrieved files, exact commits, Git blob hashes and links. A retrieved file is not evidence that the package was executed. Eight focused probes execute selected unmodified upstream helpers or small CLIs on synthetic inputs; complete annotation pipelines were not run on the 191 profiles. Full-package installation/benchmarking is not claimed.

No third-party source, reference database, sample matrix, figure, generated HTML or archive is redistributed in this change. The public repository contains our implementation, tests, configuration and this audit. API license labels can be missing or ambiguous: they are discovery metadata, not permission to relicense source. Relevant declarations include CNPS.cycle Apache-2.0, ggkegg/Escher MIT, vegan and adespatial GPL, FeGenie AGPL, and RbiMs GPL. We link to external implementations and test local copies rather than vendor them under the project's license.

## Findings that change how we use these tools

### A pathway score, a supported complex and pathway completeness are different quantities

A synthetic profile with nifH=9 and no other nitrogenase entries returns 3 in the inspected CNPS.cycle and DiTing formulas. The formulas are arithmetic summaries, not tests that all catalytic subunits were recovered. Our nifHDK rule instead requires all three components; unavailable rows remain unknown. It would be misleading to switch to an arithmetic score and claim increased recovery of nitrogen fixation.

Escher's GPR mean/min choices likewise answer a display-aggregation question. In the tested example, A=9 and B=null gives an AND mean of 4.5 or minimum of 0, while both missing returns null. Those outputs cannot replace the atlas's explicit distinction between unobserved KO rows and observed zeros.

METABOLIC and DRAM provide a useful additional distinction: report support for steps separately from the status of the whole rule. We adopted that principle without relaxing our strict criteria or importing a default 75% pathway-presence cutoff.

### Version pinning is part of the biological method

The current DiTing filter emits a below-threshold best hit without the documented threshold flag; our synthetic probe reproduces this. The inspected DRAM helper, in contrast, applies the selected full/domain threshold. This is a reproducible property of these pinned functions, not a conclusion about every release or evidence that our historical annotations were generated incorrectly. The raw annotation pipeline remains insufficiently documented to make that latter claim.

PCycDB's coverage helper sums families by prefix: synthetic foo=2 and fooB=3 produces foo=5. A future adapter must match complete IDs. CNPS.cycle's nitrogen helper uses global ko rather than its explicit input. These implementation defects are separate from differences in valid scientific estimands. We did not alter the upstream projects, open issues, or claim a correction accepted by their authors.

The examined RbiMs call path uses Wilcoxon/BH, not ALDEx2. Its directional bias is the direction of a statistical contrast, not a thermodynamic or biochemical direction. Correlated KOs, shared pathway membership and dependent MAGs/community profiles cannot automatically be treated as independent binomial trials. Its normalization helper also mixes row-wise transformations with column-wise proportions on a documented feature-by-MAG matrix; an adapter would need an explicit orientation test and ID matching before any reuse. A publication description does not establish that a particular development checkout implements that same method.

### A named statistical package does not resolve an uninformative design

MaAsLin 3's two components are relevant, but prevalence, positive individual-sample abundance and log2 positive study-coordinate mean representation are distinct outcomes. Our current group detection fractions are not individual Bernoulli observations. TSS-normalizing only the selected cycle genes would change the denominator; applying a cross-feature median correction to a curated, biologically enriched panel would change its reference population. Neither should happen silently.

The selected MaAsLin TSS helper agrees with our full-input denominator for positive entries, but masks zeros for its abundance model. That masking is not permission to convert unavailable rows into measured nondetections. Full MaAsLin fitting remains a candidate for a correctly specified biological-unit dataset with a defined feature universe and study structure, followed by fresh design-specific calibration.

PERMANOVA requires exchangeable permutations; dispersion checks answer a different question. Adjusted R2 may be negative and is not a positive variance fraction by fiat. Spatial eigenvectors require an appropriate distance/graph construction. GAM smooths require explicit fitting and diagnostic choices. Blocked predictive validation must refit preprocessing inside training folds and prevent study/BioSample leakage. Leave-study-out changes in an explanatory slope are sensitivity diagnostics, not held-out predictive skill.

## Implemented changes

1. **Logical block evidence for all eight panels.** The new [exporter](../scripts/12_gene_environment/template/block_evidence.py) evaluates each top-level AND block of the frozen rule. A plus-linked mandatory complex remains a single block. Alternative branches and optional subunits retain the existing logic. For each run, rule and record threshold (1 or 2), it reports detected, not-met and unresolvable blocks, plus bounds:
   - lower = detected blocks / total blocks;
   - upper = (detected + unresolvable blocks) / total blocks.

   These are logical bounds conditional on annotation availability, not confidence intervals, abundance estimates or evidence of a complete pathway in one organism. Logical blocks need not correspond one-to-one to biochemical reactions. Strict whole-rule outputs remain unchanged. Files are written only to the external run directory: outputs/rule_block_evidence.tsv.gz, outputs/rule_block_definitions.tsv and outputs/rule_block_interpretation.json.

2. **Conditional predictor-information diagnostics.** The [shared fitting helper](../scripts/12_gene_environment/template/analysis_nitrogen/scripts/12_gene_environment/12B_BUILD_NITROGEN_PILOT.py) now residualizes each within-study predictor against the other predictors before measuring its support. If z is that residual vector and I_s=sum(z_s^2), the study share is I_s/sum(I_s). It reports the largest share, the fraction of marginal variation remaining, the count of studies with non-negligible share, and 1/sum(share^2). The last quantity describes concentration of design information, not biological replication or Satterthwaite degrees of freedom. Existing marginal information columns remain for backward compatibility and must not be read as conditional information.

   This is an original Frisch–Waugh–Lovell calculation, motivated by the support/dependence issues exposed during review. It is not copied from MaAsLin, mgcv or clubSandwich, and it does not correct a P value. Coefficients, scaling, group weights, leave-study-out ranges and the annotation-yield sensitivity fit remain unchanged.

3. **Executable upstream reference probes.** [The probe driver](../tools/check_functional_reference_implementations.py) checks exact Git blob hashes before running selected functions. It demonstrates the three implementation defects above, compares 32 binary rule cases with ggkegg, and checks MaAsLin TSS, Escher GPR and DRAM score filtering. The ggkegg helper uses a base-R data.frame output constructor in place of tibble; its evaluation body is unchanged. Escher's relevant constants and helpers are extracted unchanged from the pinned source. These scoped accommodations are not represented as full package execution.

4. **Atlas attribution.** The generator now distinguishes software actually executed, biological reference sources and separately tested candidate implementations. Reviewing or citing a program does not mean it generated our results.

## Validation on the existing 191 profiles

The updated prepare workflow completed using the original accepted archive inputs, matched by run_accession, with no change to cohort membership or original files. Comparison with the accepted archive found all 13 pre-existing numeric diagnostic columns unchanged within 1e-10 tolerance across 186 nitrogen rows and 1,563 remaining-panel rows (1,749 total). This includes the historical coefficients and sensitivity ranges.

The new block report contains 37,054 records: 97 rules × 191 profiles × two thresholds. All block counts sum to their denominators and all bounds satisfy 0 <= lower <= upper <= 1. This is an implementation check, not validation of the biological interpretation of every rule. New invariants test mandatory complexes, alternatives, optional and unknown entries, fixed-effect/FWL coefficient equivalence, scale invariance, balanced study support and rank deficiency.

The original calibration conclusions are not overturned. No observed-gene P/q values, new significant associations, additional metagenomes or inferred fluxes were created by this audit. New cohorts and any changed inferential model require fresh calibration. We did not rerun a large Monte Carlo study solely for descriptive additions that leave the calibrated estimands unchanged.

## Inputs needed for the next annotation release

Keep the original environmental metadata schema. The following belong in separate annotation-provenance files, not extra environmental columns:

- Immutable run, gene/ORF and contig identifiers; sequences or a resolvable gene catalogue; gene coordinates/orientation and MAG assignments where available.
- Database release/hash, software version/commit, search command and every per-hit score, score type, model threshold, E-value, model/query coverage, identity where applicable, and acceptance/ambiguity status. Preserve rejected and competing hits outside the final count matrix.
- Exact gene-to-family mapping and deduplication policy. Multiple annotations, domains and reused KOs must not silently multiply biological observations.
- If read-based quantification is supplied: raw mapped counts, gene/effective lengths, coverage, library totals and multimapping policy, with a declared denominator. Store these as a separate measurement type; do not overwrite predicted-protein record counts or call them TPM.
- An explicit feature-availability universe distinguishing searched-but-not-detected features from features unavailable under the annotation release. Sequence-based uncertainty cannot be reconstructed from the current aggregate matrix.

These enable METABOLIC/DRAM for genome-level support, FeGenie for iron, dbCAN for carbohydrate families/substrates, HydDB for hydrogenase groups, CANT-HYD for hydrocarbon families, and curated N/S/P/methane databases for specificity checks. They do not by themselves establish activity or net flux.

## Reproduce the audit checks

Keep upstream checkouts outside this repository at SOURCES/owner/repository and check out the exact commits in the manifest. Do not add them, their databases or their generated outputs to this repository.

```bash
python tools/check_functional_reference_implementations.py \\
  --sources /absolute/path/to/upstream-checkouts \\
  --output /absolute/path/to/local-results/reference-probes.json
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m unittest discover -s tests -p 'test_functional_*.py'
```

The reference probes require Python with NumPy/pandas/click, base R and Node. They do not run HMM searches, mapping, full MaAsLin models, GAMs or spatial cross-validation. Run the normal [gene-biogeography workflow](GENE_BIOGEOGRAPHY.md) in a fresh directory to obtain the added diagnostics for either the current or a new matrix. Do not reuse an old prepared directory after changing its frozen code.
